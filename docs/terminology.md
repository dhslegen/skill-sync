# 用户文案术语对照表

全部用户可见文案走 i18n 资源(架构铁律 6),**禁止出现左列 git 术语**,一律使用右列产品用语。
错误提示必须附"下一步动作"(如:网络不通 → 检查是否连接公司内网/VPN)。

| 禁用(git 术语) | 使用(产品用语) |
|---|---|
| commit / 提交(git 义) | 保存 |
| push / 推送 | 分享 |
| pull / fetch / clone / 拉取 | 获取 |
| repository / repo / 仓库 | 技能库 |
| branch / 分支 | (不出现) |
| PR / merge request | 提交审核 |
| merge / 合并(git 义) | (不出现) |
| token(面向非研发) | 登录凭证 |
| sha / commit id | 版本标识(仅以等宽短码展示,不解释) |

## 已撤销的实现术语(v6 一期 + 二期,2026-08-27)

除 git 术语外,下面这批**实现词**也一并禁止出现在用户可见文案里。它们描述的是
代码内部的机制,而产品层只承认「**一个技能,三个在哪**」这一套说法:
**这台电脑上 / 各个工具里(每个工具一个勾)/ 技能库里**。

| 禁用(实现术语) | 使用(产品用语) |
|---|---|
| 关联 / 链接 | 在某个工具里**启用** / **用得到** |
| 修复关联 | (不出现)——它不是一个按钮,就是「启用到某工具」那个**勾**本身 |
| 收编 | (不出现)——本体住原地不搬,没有"收编"这个动作 |
| 记账 | (不出现)——账本是实现细节,界面只说"这台电脑上有没有" |
| 占位 | (不出现)——说「那个位置上已经有一份内容不同的技能」 |
| 纳入管理 / 移出管理 | (不出现,v6 一期撤销)——归属看技能库里记的分享者 |
| 其他工具装的 | (不出现,v6 一期撤销)——只说来源技能库,不说装它的工具 |

**三条通道各有守卫,但都有盲区,加新文案时要知道自己在哪条通道上**:
- `src/i18n/zh-CN.json` → `src/i18n/index.test.ts`(只扫这一个文件);
- Rust 侧 `AppError::new` 与 `BatchOutcome::Skipped`/`SkippedSkill`/`UnlinkResult` 的
  `reason` 字面量 → `src-tauri/tests/terminology.rs`(**按调用锚定**,写成闭包传参就抓不到);
- `README.md` 与 `RELEASE_NOTES.md` → 同一个 `terminology.rs` 里的两条(**只查这张表,
  不套 git 术语表**——那两个文件的后半截是给开发者看的)。

⚠️ **`docs/部署分发指南.md` 里的「关联」是刻意保留的**:那份文档面向部署它的 IT/管理员,
描述的是 junction/符号链接这一层的机制,不是产品界面用语。

按钮文案短促(UI 规范 §2.7):「安装」不是「立即获取 →」;「已启用」不是「启用成功!」。
